# UI 手工测试清单（Bookmark Manager v1.0.0）

> 依据：`bookmark-manager-requirements.md` §7.3（交付前必须逐项执行）
> 版本：v1.0.0（2026-08-09 发布包）
> 测试对象：`dist/bookmark-manager-v1.0.0-win64/bmk-gui.exe`（Windows x64 便携版）
> 执行人：＿＿＿＿＿＿　日期：＿＿＿＿＿＿　结果：通过 □ / 不通过 □

**说明**
- 每项含：操作步骤 / 预期结果 / 判定标准（对应 FR 编号）。
- “通过”= 预期结果全部符合；任一不符则记录到“缺陷记录表”（文末）。
- 建议准备：可联网环境（抓取/校验/代理）、Chrome 与 Firefox 导出的书签 HTML 各一份、一个本地 git 仓库与一个 GitHub 测试私有仓库、一个 MinIO（或 S3 兼容）实例。
- 如使用自定义数据目录：`bmk-gui.exe --data-dir <目录>`；默认数据目录 `%APPDATA%\BookmarkManager`。

## 1. 应用启动与设置（P0 冒烟）

### T-01 首次启动与数据目录创建（FR-01）
- **步骤**：
  1. 使用空的自定义数据目录（如 `C:\qa\bmk-data-new`）启动 `bmk-gui.exe --data-dir C:\qa\bmk-data-new`。
  2. 观察启动过程与数据目录。
  3. 正常退出后再次启动同一数据目录。
- **预期**：
  1. 应用正常显示主窗口，无报错弹窗。
  2. 数据目录自动创建 `backups/`、`logs/` 子目录与 `bookmarks.db`（含 `-shm`/`-wal`）。
  3. `logs/app.log` 记录 `schema initialized at version 1` 与 `app started`。
  4. 第二次启动不报错、数据不丢。
- **判定标准（FR-01 验收）**：首次启动自动创建目录与空库；重复启动不报错。

### T-02 主题切换（浅色/深色）（FR-01）
- **步骤**：工具栏“设置”→ 主题选项 → 切换“深色”→ 应用 → 观察界面；切回“浅色”。
- **预期**：窗口背景、列表、文字、按钮配色随主题变化；深色下文字可读、无刺眼白底残留；重启后主题保持。
- **判定标准（FR-01 §1.2）**：主题设置生效且持久化。

### T-03 界面语言切换（FR-01）
- **步骤**：设置 → 语言 中文/English 切换后重启应用。
- **预期**：主界面、菜单、对话框文案整体切换；无中英混杂遗漏。
- **判定标准（FR-01 §1.2 / §5.6）**：中英两套文案可用，默认中文。

### T-04 数据库损坏提示与恢复引导（FR-01）
- **步骤**：退出应用后，用任意编辑器把 `bookmarks.db` 头部写坏（或拷贝非 SQLite 文件覆盖），再启动。
- **预期**：不崩溃；提示数据库损坏，给出“从最近备份恢复”或“重新初始化空库”选择；选择恢复后数据从备份回来。
- **判定标准（FR-01 验收）**：损坏库场景能提示并可恢复。

## 2. 添加网址（FR-02 / FR-03 / FR-04）

### T-05 添加合法网址并抓取标题/图标（FR-02、FR-03）
- **步骤**：工具栏“添加”（或 `Ctrl+N`）→ 输入 `https://example.com` → 等待抓取 → 保存。
- **预期**：
  1. URL 校验通过，标题自动填充（抓取成功为页面标题，否则为 host），图标预览出现（抓取成功或默认图标）。
  2. 保存后列表立即出现该记录，显示标题、URL、分类“未分类”、有效性“未校验”。
  3. `logs/app.log` 无 ERROR。
- **判定标准（FR-02 验收）**：添加一条合法网址成功入库并立即显示。

### T-06 非法 URL 拒绝（FR-02）
- **步骤**：添加对话框中输入 `ftp://x`、`http://`、含空格的 URL、`javascript:alert(1)`，逐一尝试保存。
- **预期**：http/https 之外的 scheme 与非法 URL 被拒绝，对话框给出原因提示；保存不成功。
- **判定标准（FR-02 验收）**：非法 URL 被拒绝。

### T-07 重复 URL 提示（FR-02）
- **步骤**：先添加 `https://example.com/abc`，再添加 `http://example.com/abc`（归一化后重复）→ 保存。
- **预期**：提示“该网址与现有收藏重复（<现有标题>），是否仍要保存？”；确认后可保存，取消则不保存。
- **判定标准（FR-02 §4 / FR-15）**：重复 URL 出现提示。

### T-08 默认图标兜底（FR-03、FR-04）
- **步骤**：添加一个无图标网站（如本地不可达/无 favicon 的地址，可用 `--no-fetch` 场景或断网添加）。
- **预期**：列表中该记录显示内置默认图标（不报错、不空白）；数据库 `icon` 保持 NULL。
- **判定标准（FR-04 验收）**：无图标网址在列表中均显示默认图标。

### T-09 图标服务开关（FR-03 §6）
- **步骤**：设置 → 关闭“图标服务”→ 添加一个无本地 favicon 的网址 → 观察日志是否发起外部图标请求。
- **预期**：关闭后不请求 `icons.duckduckgo.com` / `google.com/s2/favicons`（日志/抓包可验证）；仅走本地解析与 `/favicon.ico`。
- **判定标准（FR-03 验收）**：关闭图标服务后不发起外部请求。

## 3. 编辑网址（FR-05）

### T-10 双击打开编辑对话框（FR-05、FR-20）
- **步骤**：列表双击一行（或选中后 `Ctrl+E` / 右键“编辑”）。
- **预期**：编辑对话框打开，字段：标题、URL、分类、标签、图标；只读字段（创建时间、有效性、状态码、最近校验时间）不可编辑。
- **判定标准（FR-05 验收）**：双击可打开编辑对话框。

### T-11 修改标题/分类/标签并保存（FR-05）
- **步骤**：编辑对话框修改标题为“新标题”，分类选“技术/前端”，标签加“dev”，保存。
- **预期**：列表与分类计数刷新；`updated_at` 更新；重启后修改保持。
- **判定标准（FR-05 §5）**：所有可编辑字段修改后正确落库并刷新界面。

### T-12 修改 URL 触发重抓与重算 url_key（FR-05 §3）
- **步骤**：编辑对话框把 URL 改为另一个地址 → 保存时选择“重新抓取”。
- **预期**：提示“是否重新抓取标题与图标？”；确认后标题/图标更新；`url_key` 重算；若新 URL 与现有记录重复出现 FR-02 重复提示。
- **判定标准（FR-05 §3）**：URL 变更后重抓与重算正确、重复提示生效。

### T-13 图标手动指定与恢复默认（FR-04 §3）
- **步骤**：编辑对话框 → 选择本地 PNG/JPEG/ICO 文件（≤512 KiB）作为图标 → 保存；再编辑 → “恢复默认”。
- **预期**：指定后列表图标变为所选图片；恢复默认后回到默认图标（icon 置 NULL）。
- **判定标准（FR-04 §3）**：手动指定/恢复默认生效。

## 4. 删除网址（FR-06）

### T-14 删除单条（二次确认 + 备份）（FR-06）
- **步骤**：选中 1 条 → 右键“删除”（或 `Delete` 键）。
- **预期**：
  1. 出现二次确认框，显示将删除数量（≤5 条列出标题）。
  2. 确认后记录从列表消失；`<数据目录>/backups/deleted_<时间戳>.html` 生成，内容含被删记录。
  3. `deleted_log` 有审计记录（可从数据库查询）。
- **判定标准（FR-06 验收）**：删除前必须出现确认框；删除后备份文件存在且含被删记录。

### T-15 取消删除（FR-06）
- **步骤**：删除确认框点“取消”。
- **预期**：记录保留，不生成备份文件。
- **判定标准（FR-06 §2）**：取消不执行任何写入。

### T-16 备份写入失败中止删除（FR-06 §3 边界）
- **步骤**：将 `backups/` 目录设为只读（或手动改权限）→ 删除一条。
- **预期**：提示备份失败，删除中止；记录仍存在。
- **判定标准（FR-06 §3 边界）**：不允许无备份删除。

### T-17 删除后通过备份 HTML 恢复（FR-06 边界 / FR-07）
- **步骤**：删除一条记录后，用“导入”功能导入刚才的 `deleted_<时间戳>.html`。
- **预期**：被删记录完整恢复（标题、URL、标签、图标）。
- **判定标准（FR-06 §4）**：已删除内容可通过该 HTML 文件导入恢复。

## 5. 导入导出（FR-07 / FR-08）

### T-18 Chrome 书签导入（FR-07）
- **步骤**：从 Chrome 导出书签 HTML → 工具栏“导入”→ 选择该文件。
- **预期**：导入完成弹出结果报告（新增 N / 跳过 N / 失败 N）；分类树、标题、URL、标签、图标（data URI）与源一致；重复条目默认被跳过并计数。
- **判定标准（FR-07 验收）**：Chrome 导出文件导入后数据一致。

### T-19 Firefox 书签导入（含 TAGS）（FR-07）
- **步骤**：从 Firefox 导出书签 HTML → 导入。
- **预期**：Firefox 的 `TAGS` 属性被正确拆分为标签；层级与源一致。
- **判定标准（FR-07 验收）**：Firefox 导出文件导入后数据一致。

### T-20 GBK 编码文件导入（FR-07 §1）
- **步骤**：准备一份 GBK 编码的书签 HTML → 导入（自动识别；必要时手动选 GBK）。
- **预期**：中文标题不乱码；自动识别失败时手动覆盖有效。
- **判定标准（FR-07 §1 / §5.4-3）**：GBK 文件正确导入。

### T-21 无效书签文件提示（FR-07 边界）
- **步骤**：导入一个无 `<DL>` 结构的普通 HTML 或损坏文件。
- **预期**：提示“不是有效的书签文件”并中止；应用不崩溃。
- **判定标准（FR-07 边界）**：损坏文件被拒绝且不中断。

### T-22 导出为标准 HTML（FR-08）
- **步骤**：工具栏“导出”→ 选择“全部”→ 保存为 `bookmarks_<时间戳>.html`。
- **预期**：文件为 UTF-8、LF 换行、Netscape 格式；分类映射为嵌套 `<DL><H3>`；未分类在根 `<DL>`；含 `ADD_DATE`/`LAST_MODIFIED`/`TAGS`/`ICON` data URI。
- **判定标准（FR-08 验收）**：导出文件可被 Chrome/Firefox 重新导入且属性不丢失。

### T-23 导出后 round-trip 验证（FR-08）
- **步骤**：将 T-22 导出的文件再导入一次。
- **预期**：结构与属性一致（round-trip 通过），无重复新增（默认跳过）。
- **判定标准（FR-08 验收）**：应用内导出→导入 round-trip 通过。

### T-24 导出当前筛选结果（FR-08 §1）
- **步骤**：设置筛选（如标签=工作）→ 导出 → 范围选“当前筛选结果”。
- **预期**：导出文件只含筛选结果，顺序与当前列表一致。
- **判定标准（FR-08 §1 / FR-12 §4）**：筛选结果可导出。

## 6. 排序（FR-09）

### T-25 各列排序（FR-09）
- **步骤**：分别点击列头“标题 / URL / 添加时间 / 分类 / 有效性 / 状态码 / 最近校验时间”，观察升/降序箭头与结果。
- **预期**：
  - 标题/URL/分类：不区分大小写按 UTF-8 码点；
  - 时间/状态码：数字序，NULL 在升/降序均排最后；
  - 有效性：升序 `0 → NULL → 1`，降序 `1 → NULL → 0`；
  - 未分类（NULL 分类）排最后；同值按 id ASC 稳定。
- **判定标准（FR-09 验收）**：各列升/降序结果与规则一致（含 NULL 与中文数据）。

### T-26 默认排序（FR-09 §3）
- **步骤**：清空筛选后观察列表默认顺序。
- **预期**：默认“添加时间 降序”（最新在前）。
- **判定标准（FR-09 §3）**：默认排序正确。

### T-31 筛选后可排序/导出/批量（FR-12 §4）

## 8. 多选 / 框选 / 右键菜单（FR-13）

### T-32 三种选择方式（FR-13 §1）
- **步骤**：① 点击行首复选框切换单行；② `Ctrl` 点击多选、`Shift` 点击范围选；③ 在列表空白处按住左键拖拽框选。
- **预期**：三种方式均能选中目标行；选中行高亮；状态栏/菜单可用项随选择变化。
- **判定标准（FR-13 §1）**：三种选择方式可用。

### T-33 右键菜单启用/置灰规则（FR-13 §2）
- **步骤**：分别对 0/1/2+ 条选中记录打开右键菜单，核对每项可用性。
- **预期**：
  - 打开 / 编辑：恰 1 条可用；
  - 复制链接 / 删除 / 立即校验 / 批量添加标签 / 批量设置分类：≥1（或 ≥2）条可用；
  - 合并网址：≥2 条且所选 url_key 全部相同可用，否则置灰。
- **判定标准（FR-13 §2 表）**：菜单启用/置灰符合上表。

### T-34 右键“打开”与“复制网址”（FR-13）
- **步骤**：选中 1 条 → 右键“打开”；选中多条 → 右键“复制网址”→ 粘贴到文本编辑器。
- **预期**：系统默认浏览器打开该 URL；复制内容为多条 URL 按行分隔。
- **判定标准（FR-13 §2）**：打开/复制行为正确。

### T-35 批量添加标签 / 批量设置分类（FR-13）
- **步骤**：选中 ≥2 条 → 右键“批量添加标签”→ 输入“qa” → 确定；再“批量设置分类”→ 选“技术”。
- **预期**：单事务生效，全部选中项标签/分类更新；提示“已为 N 条记录添加标签”；列表与分类计数刷新。
- **判定标准（FR-13 §2/§3）**：批量操作事务正确且有反馈。

## 9. 查重与合并（FR-15 / FR-16）

### T-36 查重分组（FR-15）
- **步骤**：准备多条归一化后重复的 URL（如 `https://example.com/abc` 与 `http://example.com/abc`）→ 工具栏“查重”（或 `Ctrl+D`）。
- **预期**：查重对话框列出重复分组（按 url_key），每组显示成员（标题、URL、有效性、创建时间）；显示总重复条数；支持全选/全不选；查重本身不修改数据。
- **判定标准（FR-15 验收）**：重复分组与预期一致。

### T-37 合并前必须确认（FR-16 §2）
- **步骤**：在查重对话框勾选一组 → “合并选中组”。
- **预期**：出现确认对话框（列出每组摘要：成员条数与标题），“取消”不执行任何写入；“合并全部”/“逐组确认”模式可用。
- **判定标准（FR-16 验收）**：确认前不执行任何写入。

### T-38 合并结果符合规则（FR-16 §3）
- **步骤**：对一组（主记录为最早 created_at）执行合并。
- **预期**：合并后主记录：标题/URL 取主记录；图标主记录为空时取组内第一条非 NULL；分类主记录优先、NULL 取最早非 NULL；标签为组内并集；校验字段取 last_checked_at 最新；created_at 保持、updated_at=合并时刻。
- **判定标准（FR-16 §3）**：合并后主记录属性符合规则。

### T-39 合并备份与可追溯（FR-16 §4）
- **步骤**：合并后检查 `backups/` 与 `deleted_log`。
- **预期**：合并前生成备份文件（含被合并删除的全部记录）；deleted_log 有审计记录。
- **判定标准（FR-16 §4 / FR-21）**：备份文件与 deleted_log 可追溯。

### T-40 右键合并（FR-16 §1）
- **步骤**：选中 2 条 url_key 相同的记录 → 右键“合并网址”。
- **预期**：走确认流程后完成合并，结果同 T-38。
- **判定标准（FR-16 §1 / FR-13 §2）**：右键合并可用。

## 10. 批量校验（FR-14）

### T-41 校验范围与判定（FR-14）
- **步骤**：对一批记录（含可访问、404、403/429、超时站点）执行工具栏“校验”或右键“立即校验”。
- **预期**：
  - 2xx → 有效（绿点）；
  - 4xx/5xx → 无效（红点），status_code=实际码；
  - 403/429 → 待复测（黄点 + “待复测”），valid 保持原值；
  - 网络失败 → 无效，status_code=0，note 为 `dns_failed/timeout/connect_failed/tls_failed/network_error`；
  - 405 → 自动降级 GET 复核。
- **判定标准（FR-14 §5 验收）**：判定全部符合规则。

### T-42 校验进度与取消（FR-14 §8）
- **步骤**：对大批量（如 100+ 条）启动校验 → 观察进度对话框 → 中途点“取消”。
- **预期**：进度条、成功/失败/待复测计数、日志区（脱敏）实时更新；取消后已写入结果保留；界面不卡顿（并发下 UI 响应正常）。
- **判定标准（FR-14 §8/验收）**：并发下 UI 不卡顿；取消后可继续使用。

### T-43 待复测与代理自动重试（FR-14 §7、FR-17）
- **步骤**：设置校验代理为“自动”，配置一个可用 VLESS 节点；对 403/429 站点校验。
